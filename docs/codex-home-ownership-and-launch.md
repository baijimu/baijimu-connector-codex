# Codex 工作区状态目录所有权与启动规范

## 结论

客户端维护一个 Codex 工作区目录。现有系统 `~/.codex` 原样登记为“默认工作区”，用户新建工作区和旧版已经建立的独立 Codex Home 与它并列；每个工作区拥有独立的会话、历史、技能、配置和状态数据库。ChatGPT 登录与百积木工作区授权属于全局认证通道目录，每个 Codex 工作区独立选择一个认证通道。安装状态与工作区管理是互斥主视图：安装未完成时只展示安装状态，安装成功后展示全部工作区。后台路由验证属于已安装环境的告警状态，不得让界面退回安装视图。

## 所有权边界

百积木只在创建工作区或用户明确切换认证通道时管理目标 Codex Home 中的：

- `auth.json`：当前显式选择的文件型授权；
- `config.toml` 中的模型 provider、登录方式、认证存储方式和百积木 provider 表；
- `.baijimu-owner.json`：目录所有权与受管文件声明；不包含业务工作区 ID 或凭证明文。

以下内容在同一个 Codex 工作区的不同认证通道间共享，初始化、切换和重新授权均不得移动、删除或重建；不同 Codex 工作区之间不共享这些状态：

- 会话、任务和历史记录；
- SQLite 与其他 Codex 状态数据库；
- 日志、技能、缓存和用户自定义文件；
- `config.toml` 中不属于百积木的配置项。

每个认证通道自己的 credential 保存在 Connector 私有数据目录的哈希键目录中。运行时路径不得暴露百积木工作区 ID，也不得把 credential 写入进程参数、日志或用户环境变量。

## 初始化

1. 验证当前设备确实获得目标工作区授权。
2. 已有有效的私有 credential 时幂等复用；缺失时只在首次初始化中签发。
3. 将 credential 写入 Connector 私有认证通道档案，不触碰任何未选择该通道的 Codex 工作区。
4. 系统默认工作区尚未选择任何认证通道时，首次初始化可选择该通道；否则只新增认证通道。
5. 安装器只验证默认工作区初始化结果，不自行覆盖其他工作区文件。

安装和初始化不得接管或替换既有 ChatGPT 登录。无法解析现有 `config.toml` 时必须明确失败，不得静默覆盖。

## 授权切换

切换必须遵循固定顺序：

1. 用户在目标 Codex 工作区的认证选择弹窗中选择目标档案并确认；ChatGPT 尚未登录时允许选择官方登录通道。
2. 停止当前 ChatGPT/Codex 桌面进程，等待进程退出。
3. 归档当前授权可能刷新的认证内容和认证配置。
4. 使用同目录临时文件和原子替换更新 `auth.json` 与认证相关配置，保留其他 TOML 项。
5. 仅在写入全部成功后更新当前授权元数据；写入失败时恢复原文件、元数据和先前运行的桌面进程。
6. 返回新的当前认证通道，不启动桌面应用。

切换到百积木档案时只设置 provider、API 登录与文件型认证存储，不设置、不删除也不归档 `model`；模型由 Codex 自身或用户选择。切换到 ChatGPT 登录时移除百积木 provider 选择和 API 授权，设置官方 ChatGPT 登录方式；完成登录后，后续切换会归档个人认证以便往返。

新建 Codex 工作区的 `config.toml` 不写入 `model`。历史工作区中已经存在的 `model` 可能是用户显式选择，升级和认证切换必须原样保留，不得根据旧产品默认值推断并删除。

Windows 直接调用安装包声明的稳定 `codex:` 协议，由 Windows Shell 解析当前安装版本；运行期不得为定位
可执行文件枚举 AppX 包或读取应用清单。工作区切换需要停止既有桌面进程时，只查询版本化产品配置声明的
进程名，并在执行停止前校验可执行文件具有有效且受信任的 OpenAI Authenticode 签名。AppX 包身份、最低
系统版本和安装位置只属于安装与升级校验职责。该路径不得写 `HKCU\Environment`，不得调用
`SendMessageTimeout` 或发送 `WM_SETTINGCHANGE`。

macOS 使用系统安装的 ChatGPT/Codex 应用路径启动，并从子进程环境中移除 Connector 私有变量和继承的 `CODEX_HOME`。

## 打开与重启工作区

“打开工作区”只把工作区目录中已登记的精确 `codexHome` 传给桌面启动入口；“重启 Codex”只重启当前活动工作区。两者都不接收认证档案参数，也不得读取、写入或回滚 `auth.json`、`config.toml` 和授权元数据。用户可以先切换认证通道，再独立决定是否打开或重启。

## 重新授权

重新授权只签发并更新目标百积木认证通道的私有 credential，并同步所有已经选择该通道的 Codex 工作区认证文件。当前活动工作区使用该通道时，先停止桌面应用，但不自动重启；用户从当前工作区显式执行重启。没有选择该通道的工作区不得受到影响。

## 启动、状态读取与旧版本升级

元数据版本升级时：

- 从每个旧工作区 Home 的 `auth.json` 读取 credential 并写入 Connector 私有认证通道目录；
- 只从旧元数据能够精确推导的受管目录发现历史 Codex Home，并验证目录类型、所有权标记和 profile key；不得扫描或认领任意用户目录；
- 将每个真实存在的旧 Codex Home 以稳定本地 ID 幂等登记为“历史导入”工作区，保留原路径、状态和认证通道映射，与默认及新建工作区并列；
- 已经登记的路径不得重复导入，所有权冲突必须停止并报告，不得猜测归属；
- 始终建立可选的 ChatGPT 登录档案，没有历史个人凭证时标记为“需登录”；
- 禁止在发现和登记过程中改写任何历史工作区的 `auth.json`、`config.toml`、会话或数据库；
- 旧隔离目录、会话、数据库、日志和配置全部保留原位，并可通过导入后的工作区正常打开；
- 不自动合并多个状态库，避免主键、任务和 SQLite 状态冲突。

客户端进程启动、健康检查和重复刷新除幂等登记新发现的历史工作区外，不得修改任何 Codex Home。旧版本遗留的用户级 `CODEX_HOME` 只允许在能证明由 Connector 写入且用户显式确认时清理。清理后提示用户重启既有终端；不做 Windows 环境广播。
