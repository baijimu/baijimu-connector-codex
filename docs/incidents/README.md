# 故障库

保存可以复用的诊断证据与恢复方法，归属本仓库维护者。其他组件的故障记录应保存在各自权威仓库，并互相链接，避免复制多个会失去同步的版本。

先搜索错误码、症状、组件与受影响版本；匹配错误文字后仍要验证触发条件，不能直接照搬修复命令。代码修复、发布、客户数据迁移和业务恢复分别记录状态，不能用“版本已升级”代替恢复验收。

## 记录规则

- 每个故障一个稳定编号，标题写症状与触发条件；再次出现时补充同一条记录的时间线，不新建重复结论。
- 区分已观测事实、复现结论和待验证假设。记录排除项及证据，避免后续重复排查。
- 记录影响范围、版本、修复提交和升级路径；写清楚历史修复的适用条件及未覆盖范围。
- 操作步骤包含前置检查、备份、执行、验证和回滚；查询、正常启动不执行迁移、补建、导入或修复。
- 只有取得业务恢复证据才标记恢复；无法验证用户原业务时明确写“等待原业务验证”。
- 公共记录使用脱敏路径和身份。日志、截图、凭据、客户设备标识留在受控工单或设备本地；不提交原始用户会话或令牌。
- [模板](TEMPLATE.md) 用于后续记录。对已有条目的修订随代码评审，过时步骤标明适用版本及替代记录。
