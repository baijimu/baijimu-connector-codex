# 桌面管理器显式工作区与 CLI 授权范围

2026-10-22 在用户指定 Windows 设备上确认：管理器 2.1.6 仍从 CLI `auth status.currentWorkspaceId` 取得目标；CLI 0.128.0 已取消默认工作区。设备返回 authenticated=true、固定授权包含所选目标，显式 workspace get 成功，但管理器把字段缺失误报为没有工作区授权。

本次客户端本地应用修复版 2.1.7 移除该依赖。安装目标由页面明确选择，或使用当前 Codex 工作区已绑定认证通道的工作区身份；首次安装不按凭据数量或列表顺序推测。所有工作区业务 CLI 命令显式传参，重试保持原任务目标。已安装且未请求百积木工作区操作时保留个人 ChatGPT 使用方式。

CLI `allUserWorkspaces=true` 不要求枚举 workspaceIds。固定范围和动态范围统一判断，目录展示与服务端当前成员事实取交集；初始化和重授权仍通过 CLI 精确工作区操作，由 Owner 校验实际成员和业务权限。失败明确返回，不读取或修补 CLI 凭据、不恢复默认工作区、不加旧协议回退或可用性探测。

## 单独批准的依赖变更

当前用户在本会话明确批准：“批准：CLI 最低版本改为 0.128.0”。准确范围为管理器 connector.json 中 managedToolDependencies 的 baijimu-cli.minimumVersion：0.29.0 → 0.128.0。CLI 的平台工具 Owner 负责发行；管理器依赖其现行显式工作区及 allUserWorkspaces 合同。保持旧下限无法保证合同，本次不实施旧协议分支。未添加、移除、替换或更新 Rust/npm 包及其传递依赖，也不发布 Bridge Agent 或 CLI。

旧设备必须由宿主安装满足下限的托管 CLI。目标 Windows 已为 0.128.0。验证包括无默认工作区、固定范围、动态范围为空枚举、未授权/成员撤销、Owner 拒绝、明确目标传递、原任务重试与个人认证。78 项 Rust 回归及相关 UI 回归在版本变更前通过；发行以准确主线提交的专属三平台流水线结果为准。

恢复按独立发布单元处理，不移动不可变标签、不覆盖制品；管理器 2.1.6 与 CLI 0.128.0 的组合仍有此缺陷，不能将回退管理器单独视作有效恢复。设备验收失败停止推广并发布后继修复，不自动降级托管 CLI、不修改其凭据。
