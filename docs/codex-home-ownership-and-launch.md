# Codex 默认状态目录所有权与启动规范

## 结论

Codex 始终使用当前系统账户唯一有效的 Codex Home，客户端把它展示为“Codex 默认工作区”。ChatGPT 登录与百积木工作区是该工作区内的独立认证通道，不是不同工作区目录；切换认证通道不得切换或复制会话、历史和状态。安装状态与默认工作区是互斥主视图：安装未完成时只展示安装状态，安装成功后只展示默认工作区。后台路由验证属于已安装工作区的告警状态，不得让界面退回安装视图。

## 所有权边界

百积木只在用户明确切换授权档案时管理 Codex Home 中的：

- `auth.json`：当前显式选择的文件型授权；
- `config.toml` 中的模型 provider、登录方式、认证存储方式和百积木 provider 表；
- `.baijimu-owner.json`：目录所有权与受管文件声明。

以下内容在 ChatGPT 与所有百积木工作区授权间共享，初始化、切换和重新授权均不得移动、删除或重建：

- 会话、任务和历史记录；
- SQLite 与其他 Codex 状态数据库；
- 日志、技能、缓存和用户自定义文件；
- `config.toml` 中不属于百积木的配置项。

每个工作区自己的 credential 保存在 Connector 私有数据目录的哈希键目录中。运行时路径不得暴露工作区 ID，也不得把 credential 写入进程参数、日志或用户环境变量。

## 初始化

1. 验证当前设备确实获得目标工作区授权。
2. 已有有效的私有 credential 时幂等复用；缺失时只在首次初始化中签发。
3. 将 credential 写入 Connector 私有授权档案，不触碰当前 Codex 登录和配置。
4. 如果现场没有任何已选择的 ChatGPT 或百积木授权，首个工作区可自动激活；否则只新增档案。
5. 安装器根据是否激活该档案验证共享 Codex Home，不自行生成或覆盖认证文件。

安装和初始化不得接管或替换既有 ChatGPT 登录。无法解析现有 `config.toml` 时必须明确失败，不得静默覆盖。

## 授权切换

切换必须遵循固定顺序：

1. 用户在默认工作区的认证选择弹窗中选择目标档案并确认；ChatGPT 尚未登录时允许选择官方登录通道。
2. 停止当前 ChatGPT/Codex 桌面进程，等待进程退出。
3. 归档当前授权可能刷新的认证内容和认证配置。
4. 使用同目录临时文件和原子替换更新 `auth.json` 与认证相关配置，保留其他 TOML 项。
5. 仅在写入全部成功后更新当前授权元数据；写入失败时恢复原文件、元数据和先前运行的桌面进程。
6. 返回新的当前认证通道，不启动桌面应用。

切换到百积木档案时设置该产品版本化配置声明的模型、provider、API 登录与文件型认证存储。切换到 ChatGPT 登录时移除百积木 provider 选择和 API 授权，设置官方 ChatGPT 登录方式；完成登录后，后续切换会归档个人认证以便往返。

Windows 直接调用安装包声明的稳定 `codex:` 协议，由 Windows Shell 解析当前安装版本；运行期不得为定位
可执行文件枚举 AppX 包或读取应用清单。工作区切换需要停止既有桌面进程时，只查询版本化产品配置声明的
进程名，并在执行停止前校验可执行文件具有有效且受信任的 OpenAI Authenticode 签名。AppX 包身份、最低
系统版本和安装位置只属于安装与升级校验职责。该路径不得写 `HKCU\Environment`，不得调用
`SendMessageTimeout` 或发送 `WM_SETTINGCHANGE`。

macOS 使用系统安装的 ChatGPT/Codex 应用路径启动，并从子进程环境中移除 Connector 私有变量和继承的 `CODEX_HOME`。

## 重启默认工作区

“重启 Codex”属于 Codex 默认工作区，不属于任何认证选项。该操作不接收认证档案参数，也不得读取、写入或回滚 `auth.json`、`config.toml` 和授权元数据；它只停止现有的受信任桌面进程，再通过系统入口重新打开 Codex。用户可以先切换认证通道，再独立决定是否重启。

## 重新授权

重新授权只签发并更新目标工作区的私有 credential。目标工作区当前生效时，先停止桌面应用，再同步默认 `.codex/auth.json`，但不自动重启；用户从默认工作区显式执行重启。非活动工作区不得影响当前桌面进程或默认认证文件。

## 启动、状态读取与旧版本升级

元数据版本升级时：

- 从每个旧工作区 Home 的 `auth.json` 读取 credential 并写入 Connector 私有凭证库；
- 所有工作区元数据的 `codexHome` 统一归一化为当前有效 Codex Home；
- 依据共享现场识别当前授权，只更新 Connector 私有元数据；
- 始终建立可选的 ChatGPT 登录档案，没有历史个人凭证时标记为“需登录”；
- 禁止把旧元数据记录的活动工作区重新写入共享 `auth.json` 或 `config.toml`；
- 旧隔离目录、会话、数据库、日志和配置全部保留原位；
- 不自动合并多个状态库，避免主键、任务和 SQLite 状态冲突。

客户端进程启动、健康检查、授权状态读取和重复刷新都不得修改共享认证文件。旧版本遗留的用户级 `CODEX_HOME` 只允许在能证明由 Connector 写入且用户显式确认时清理。清理后提示用户重启既有终端；不做 Windows 环境广播。
