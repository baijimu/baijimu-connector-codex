# Codex CLI 安装制品与升级

CLI 制品目录由本仓库 `sync-codex-upstream-artifacts.yml` 定时或手动同步。
该流程与桌面管理器、远程连接器的应用发布独立，不创建应用版本或市场记录。

macOS 与 Windows 的各架构只启用官方 `codex_package_v1` 完整包。
旧单程序/平铺压缩包保留在目录中但标记为 `deprecated: true`，新安装不得选择它们。
镜像前检查官方摘要、包内版本和目标架构，以及主程序、Code Mode Host、ripgrep 和资源目录。
缺失任一必需组件时整次同步失败，不能退回旧单程序包。

发布依次验证内容寻址资产、不可变清单，然后更新公开 `latest.json`。
维护者应核对发布工作流与公开目录，再通过远程连接器执行安装及真实工具调用验收。
完整包的版本必须与官方 Release 一致，不能把补齐组件当作另一个自行定义的 Codex 版本。

客户设备由远程连接器的 `ensureCodexReady` 检查目录要求的 CLI 版本；目录同步不代表
所有客户设备已经升级。相同版本的旧不完整安装需要调用 `setupRetry` 做一次完整重装，
传入该客户实际授权的 `workspaceId`，再回查 `setupState`、后台服务版本和工具执行结果。
仅有 `--version` 成功不能作为工具可用性的验收依据。

Codex 桌面 App 与连接器使用的独立 CLI 分别管理升级。CLI 升级通常不要求发布
Bridge 或连接器版本；官方协议变化需要适配时，才另行发布对应连接器。
