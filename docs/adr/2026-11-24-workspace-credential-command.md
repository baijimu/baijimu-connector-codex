# 改用工作区凭据签发命令

桌面管理器 2.1.9 通过宿主注入的 `baijimu` 调用顶层 `llm-credential create`。从已发布的 `baijimu` 0.159.0 起，公开命令移至 `workspace llm-credential create`。新版本会在命令解析阶段拒绝旧入口，导致首次安装和工作区重新授权无法发起签发。

2026-11-24 用户单独批准：“批准将最低版本提高到 0.159.0”。批准范围为 `connector.json` 中托管工具 `baijimu-cli` 的最低版本由 0.128.0 提升至 0.159.0。桌面管理器 2.1.10 在首次安装和重新授权中使用同一签发入口，继续传入明确工作区 ID 并校验返回凭据的归属。命令执行和凭据签发分别由 `baijimu` 和平台签发服务负责。

设备上的托管 `baijimu` 低于 0.159.0 时，Bridge Agent 会在安装或启动时报告依赖未满足，设备需先更新该托管工具。0.128.0 和 0.159.0 的已发布制品已通过 `--help` 验证命令差异。修复版本按桌面管理器的各平台流水线验证，Windows 设备验收覆盖首次安装和重新授权。恢复时保留不可变版本与现有凭据，按故障结果发布后继补丁。
