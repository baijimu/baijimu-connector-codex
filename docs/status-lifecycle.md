# 本地状态、数据初始化与慢操作

`GET /management/v1/credential-state` 只读取本地已提交的数据。它不启动 CLI、访问平台、迁移元数据、复制凭据、补建认证通道或工作区，也不导入旧目录。缺失数据返回 `localDataReady: false`；损坏或不支持的数据版本返回错误，读取不负责修复。

`POST /management/v1/prepare-local-state` 是应用内的显式数据初始化命令。按顺序调用旧元数据导入、版本迁移、初始通道补建、现场认证选择校正、默认工作区补建和历史工作区导入。每个步骤可重复执行；导入只在目标不存在时进行，旧来源在新副本持久化后才删除。不会把归档凭据重新激活到用户的 Codex 目录。`setup/ensure-ready` 与显式安装命令也在需要时调用该流程。HTTP 绑定和进程 readiness 不依赖此流程。`localDataInitialization` 单独记录本次进程的初始化结果（pending/ready/failed），失败后重试仍走显式命令；它不是凭据状态缓存。

`POST /management/v1/workspace-discovery` 单独查询平台授权和工作区。UI 先显示本地数据，再显示发现结果。凭据状态中的 `currentWorkspaceId` 和授权列表不再推测远端状态；调用方使用发现结果的同名字段。网络失败明确显示 discoveryWarning，不能把上次授权当作本次成功。最终授权判断仍由执行修改命令时的 CLI 检查负责。

## 并发边界

- 操作预留使安装、重新授权、切换工作区和桌面启停串行。新修改操作遇到已有操作立即返回 `OPERATION_IN_PROGRESS`，不在后台无限排队。
- 本地读写锁仅覆盖本机文件和环境投影的一致性读取/提交。网络签发、安装下载、桌面进程等待及 Windows 环境变更广播不持有数据锁。
- 查询在慢操作期间读取已提交状态，并返回 `operation.running`。如果恰好遇到本地多文件提交，立即返回 `STATE_COMMITTING`，由界面有界重试；不会拼接提交前后的数据，也不会返回缓存成功。
- 安装线程持有操作预留直至本地安装和桌面处理完成；随后释放，后台路由验证不占用桌面操作预留。

锁保护的是归档凭据、共享 auth/config、工作区目录及活动选择之间的一致性，不是为了保护一个 GET。删除所有同步会让读取观察到半提交状态；把外部 I/O 放进同一把锁则会重现此次故障。

## 外部进程

桌面 PowerShell 的整个执行限定为 25 秒；CLI 单次执行为 10 秒，工作区分页共用 15 秒期限。安装命令使用独立的长执行预算。超时终止本次创建的进程树并有界回收。

Windows 子进程先以 suspended 状态创建，加入启用 kill-on-close 的 Job Object 后再恢复主线程，避免在进程树纳管前派生子进程。Unix 使用独立进程组。输出写入私有临时文件，避免继承 stdout/stderr 的后代使管道读取永久不返回。输出有大小限制；临时文件随调用清理，不返回命令参数或凭据内容。

验证覆盖首次查询不补建、显式初始化幂等、重复查询不改文件内容和修改时间、长操作期间查询可用、提交期间查询立即返回、并发修改被拒绝、损坏数据不自动修复，以及成功/超时后子进程清理。Windows Job Object 运行行为必须在原生 Windows Runner 验证。
